# Limitation 局限说明（README 同步引用，面试重点）

1. **LLM-as-judge 存在主观偏差**，打分结果仅作为回归辅助，**不能替代人工抽检**，正式验收必须人工抽样复核。
2. **不支持十万级以上超大评测集**，设计目标是 POC、试点项目的回归验收，不适合大规模离线基准评测。
3. **Judge 模型本身会产生幻觉**，更换 judge 模型会改变基线分数；评测基线必须固定 judge 模型与打分 prompt。
4. **不支持复杂多轮对话长上下文评测**，当前版本优先单轮问答场景。
5. **不提供原生标注平台**，badcase 导出后需要外部标注工具完成标注。
6. **无高并发分布式设计**，适合小团队内部使用，不直接上生产高并发服务。
7. 确定性判分依赖「数值容差 / 文本归一化 / 关键片段召回」规则，**对开放式长文本的标准答案**仍需配合 LLM 裁判或人工判定。
8. 目标服务需自行封装为 `TargetService`；内置 Mock 服务仅用于演示与离线测试，**不代表真实业务效果**。
